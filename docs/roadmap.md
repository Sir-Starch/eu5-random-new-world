# Dependency-aware roadmap

All engine validation gates target the currently detected EU5 build, then repeat on future patches. The only in-game result so far is metadata recognition; the owner requested no more game launches in this session [V-GAME C11–C12]. The D0 T2 mod candidate and T3-capable world model exist offline under the [implementation contract](implementation-contract.md) and [ADR 0002](adr/0002-d0-generator-stack.md); in-game acceptance remains pending. “Opus design/implement” needs architecture and production work; “Sonnet implementable” is bounded work. See [backlog](handoff/sonnet-5.5-backlog.md).

| R10. Performance and distribution | Opus design, then Sonnet | Benchmark output generation, load time, memory, QA worlds; choose Python or native core from evidence. A full generation must be short enough to wait for in the application (12 minutes in Python, 1.5 minutes with the Rust kernels and overlapping stages, [ADR 0005](adr/0005-native-core.md), C101, C103) and must fit the player's machine (peak 7.8 GiB, 6.8 GiB on one thread; EU5 asks for 16 GB, [ADR 0006](adr/0006-machine-resources.md), C102). The first profile (C92) gave the order of work: cache what is read from vanilla once per game build, build the ten terrain decals in parallel, then move value noise, distance fields and the LZAV codec to a native core. The last two are done (C101, C103); the cache is dropped, because the stages that read only vanilla run beside the world generation and a cache would save nothing on six or more threads (C121). Gate: targets set from measured baseline, no proprietary assets in release, licensing decision by owner. |
