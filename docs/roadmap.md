# Roadmap

Phases of the project, what each depends on and the gate that accepts it. Engine gates target the installed EU5 build and are repeated after every game patch. Progress release by release is in the [changelog](../CHANGELOG.md).

**Where it stands (0.11.6, 2026-10-24).** The owner has accepted physical geography (V1) and the sea phase (S1) in game. The natives (R6) and the economy and societies of R7 load and play in game, with the remaining open points recorded in their experiments. The content plan (N0–N5) is implemented offline, and N1–N3 have been seen in console sittings. The world's mod, the generator's window and the Workshop text are written in all eleven official languages (L1, offline). The column *Kind of work* records what each phase needed when it was planned: design and production work, or bounded implementation.

| R10. Performance and distribution | Design, then bounded implementation | Benchmark output generation, load time, memory, QA worlds; choose Python or native core from evidence. A full generation must be short enough to wait for in the application (12 minutes in Python, 1.5 minutes with the Rust kernels and overlapping stages, [ADR 0005](adr/0005-native-core.md), C101, C103) and must fit the player's machine (peak 7.8 GiB, 6.8 GiB on one thread; EU5 asks for 16 GB, [ADR 0006](adr/0006-machine-resources.md), C102). The first profile (C92) gave the order of work: cache what is read from vanilla once per game build, build the ten terrain decals in parallel, then move value noise, distance fields and the LZAV codec to a native core. The last two are done (C101, C103); the cache is dropped, because the stages that read only vanilla run beside the world generation and a cache would save nothing on six or more threads (C121). Gate: targets set from measured baseline, no proprietary assets in release, licensing decision by owner. |
