# 021 — The generator of the hub, started from the game (Linux, Proton)

- **Hypothesis:** The hub mod of ADR 0009, built by `packaging/hub.py`, works from the game on Linux. Open in folder on the hub, a double-click on `Random New World Generator.exe`, and the generator's window opens inside the game's Proton prefix, finds the game and the profile, generates a world beside the running game and installs it as the world mod; applying the playset again loads that world in a new 1337 game.
- **Build:** `uv run python packaging/hub.py --replace` → `dist/rnw_exp_hub` (147 MiB, version 0.9.13). It holds the embeddable CPython 3.12.10 (SHA-256 pinned, its MD5 matching python.org), the locked Windows wheels with Qt cut to Core, Gui, Widgets and two platform plugins, our wheel built by maturin for `x86_64-pc-windows-gnu` (`_native.pyd`, metadata, licence, Rust SBOM), every module as unchecked-hash `.pyc`, and the launcher (MinGW, `asInvoker` manifest, version resource). The only programs are the launcher, `python.exe` and `pythonw.exe` (checked by the build).
- **Offline checks (mine, scratch Proton prefix with Wine's null graphics driver, so nothing shows on the desktop):**
  - [V-EXEC] The launcher with `--self-test` starts `pythonw.exe`, which loads `qwindows.dll`, `Qt6Widgets.dll` and our `_native.pyd`, and writes `window, native kernels and world codes work` to `launcher.log`; no display driver is loaded and no `.pyc` is written into the hub.
  - [V-EXEC] The hub's Python, under Proton's Wine, generates `RNW1-040G0-00000-9GDRN-V004G-T036F-9N0` in 2 min 33 s on 32 threads: all 733 files equal the reference manifest, and every file on disk matches the new manifest.
  - Two traps found on the way: a first hub copied our sources without package metadata, so `rnw/__init__.py` failed to read its version (the launcher showed the traceback, as designed; the build now installs our own wheel); a console program (`python.exe`) hangs under the null graphics driver, so offline runs use `pythonw.exe` with the output redirected.
- **Method (owner, in game):** with the game closed, install the hub (`uv run rnw install-mod dist/rnw_exp_hub USER_DIR`). Start EU5 with the usual RNW playset, without playing a campaign without the mod first (C97). Mods → Open in folder on **RNW hub with generator** (it need not be in the playset) → double-click **Random New World Generator** → in the window check that the game and the profile are found, paste the world code above, keep Install on, press Generate. When it is done, apply the playset again and start a new 1337 game.
- **What to report:** whether the window opened, what it found, the time, any message, whether the new game shows the world. I read, without writing: `AppData/Local/RandomNewWorld/` in the game's prefix (`launcher.log`, `last-error.log`, history, the generated bundle) and the game's `error.log`; the installed world is compared with the reference manifest.
- **Expected changes in the profile:** `mod/rnw_exp_hub` (new) and `mod/rnw_exp_new_world` replaced by the generated world (the probe of experiment 019 goes with it); about 1.3 GB for the bundle in the prefix's `AppData/Local/RandomNewWorld/generated/` and 1.3 GB for the installed copy.
- **Game version:** 1.4.2 open beta, build 26043558 (C84); Proton 11.0 (a community build).
- **Status:** **OPEN** — offline checks pass; the in-game run is the owner's.
