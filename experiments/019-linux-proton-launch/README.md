# 019 — Starting the generator from the game on Linux (Proton)

- **Hypothesis:** On Linux the game runs as `eu5.exe` through Proton, so the mod manager's **Open in folder** (`LocalMod.OpenInFolder`, ending in `ShellExecute`, ADR 0009) acts inside Wine. If it opens a file browser at the mod's folder, the player can start a generator placed in the mod from there.
- **Method, part 1 (owner, in game):** in the main menu's Mods window press Open in folder on an installed mod and report what opens.
- **Method, part 2 (mine, offline, no game):** run the Windows build of the generator (embeddable Python 3.12.10, the locked Windows wheels, `_native.pyd` cross-built with MinGW) under the Proton build the game uses, in a scratch prefix made by the `proton` script itself (`proton run`, so the prefix gets what the game's prefix has), with the Steam library variables Steam passes (`STEAM_COMPAT_LIBRARY_PATHS`, `STEAM_COMPAT_INSTALL_PATH`, `PROTON_SET_GAME_DRIVE`) but no `SteamAppId`; start the discovery from a real Workshop item folder of the game as Wine sees it (`S:\` and `Z:\`). The game's prefix is only read, never run in.
- **Method, part 3 (owner, in game, open):** instead of the 250 MB generator, a harmless probe ([`probe.c`](probe.c), MinGW build of 100 KB, staged as `generated/launch_probe/generator/probe.exe`, not committed) goes into the one installed test mod as `rnw_exp_new_world/generator/probe.exe`, the layout of ADR 0009, with mode 644 (no executable bit, as a Workshop download may have it). In the running game: Mods → Open in folder on `rnw_exp_new_world` → `generator` → double-click `probe.exe`. It writes `probe-result.txt` beside itself (its Windows and Unix path, Wine and host version, cores, free memory with the game running, the four Steam/Wine variables, the Documents folder, whether the profile's `mod` folder, Proton's Steam stub list and `S:\…\eu5.exe` are visible) and shows the same text in a message box. Expected: it starts without the executable bit, the box shows on the desktop, the file is written, and the game logs nothing about the extra folder. Offline check under `proton run` in a scratch prefix: the file is written as expected.
- **Files/tools:** the scratch Windows rig and prefixes (session scratchpad, not committed), `proton run`, `WINEDEBUG=warn+module` for the loader.
- **Game version:** 1.4.2 open beta, build 26043558 (C84); Proton 11.0 (a community build).
- **Result/evidence:**
  - Part 1 [V-GAME owner, 2026-10-21]: Open in folder opens Wine's own explorer at the mod's folder (`rnw_exp_new_world` with `.metadata`, `in_game`, `main_menu`). It does not open the desktop's file manager.
  - Part 2 [V-EXEC, 2026-10-21]: PySide6 6.12.0 imports and `python -m rnw.gui --self-test` passes (window offscreen, native kernels, world codes). From `S:\steamapps\workshop\content\3450310\<item>` and from the same folder under `Z:\` the generator finds the game (`S:/steamapps/common/Europa Universalis V`, build 26043558); the Documents known folder is `C:\users\steamuser\Documents`, where a stand-in profile folder was found as the Windows profile. The same Windows build had written all 733 files of continents seed `RNW1-040G0-00000-9GDRN-V004G-T036F-9N0` identical to the Linux build under system Wine 11.20 (2 min 24 s, against 1 min 34 s native).
  - A first attempt failed with `DLL load failed while importing QtWidgets`: that prefix was made by Proton's `wine` binary without the `proton` script, so it lacked ICU 68 (`icuuc68.dll`, which Wine's `icuuc.dll` forwards to) and DXVK's `d3d11.dll`/`dxgi.dll` (Qt6Gui imports `d3d11.dll`). The `proton` script links ICU 68 and copies DXVK into every prefix; the game's prefix has both [V-LOCAL]. Not a property of the player's machine.
  - [V-LOCAL] Proton's Steam stub in the game's prefix lists the libraries as `"LibraryFolders"` (`Z:\home\…\Steam`, `S:\`); Steam itself writes `"libraryfolders"`. KeyValues keys are case-insensitive, and the generator's reader now folds them, so discovery also finds the game through the stub.
- **Remaining uncertainty:** part 3 (a program started from Wine's explorer inside the running game, in the Steam Linux Runtime container); a real window on the player's display under Proton (only offscreen here); the full export under Proton's Wine (only under system Wine); memory with the game in the main menu and the generator side by side.
- **Status:** **PARTIAL** — parts 1 and 2 answered; part 3 open.
